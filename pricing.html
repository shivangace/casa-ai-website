Request Lifecycle

From agent request to verdict in milliseconds.

Every agent action passes through four stages inside CASA-AI — interception, evaluation, enforcement, and pass-through. Clean traffic flows through invisibly. Violations are severed before they reach production.

01
Interception Layer

Agent sends a request. CASA-AI intercepts the SSE stream before it reaches the LLM.

One environment variable change points your agent's LLM calls through CASA-AI instead of directly to the provider. No code changes in your agent. Every Server-Sent Events token is captured and buffered for reassembly. The agent's entire Thought-Action-Observation reasoning chain — including all intermediate steps invisible to any API gateway — is now inspected in real-time.

agent config — one line change
# Before: agent calls LLM directly — CASA-AI sees nothing OPENAI_API_BASE=https://api.openai.com # After: CASA-AI intercepts every call — zero agent code changes OPENAI_API_BASE=http://casa-ai:8088 # CASA-AI transparently proxies clean traffic through to the LLM # No agent code changes. No SDK modifications. Just this.

02
Compliance Engine

Tokens are reassembled into TAO steps. Intent graph built. OPA evaluates in <2ms.

Each SSE chunk is buffered and reassembled into complete Thought-Action-Observation steps. A PAN number split across 3 chunks is caught during reassembly — not after. Every step is classified and added to the session's live intent graph. The embedded OPA engine evaluates the complete graph against all five detection layers simultaneously — PII, injection, tools, sovereignty, exfiltration — in under 2 milliseconds per evaluation.

03
Circuit-Breaker

Breach fires. Stream severed. Credentials revoked. Audit written. All synchronous.

When a violation fires, four actions execute synchronously — not advisory, not eventually consistent. The SSE connection is dropped (the agent never receives another token), IAM credentials are invalidated via real cloud APIs, a SHA-256 chained audit entry is written, and a signed webhook alert is dispatched to your incident channel. A failed IAM revocation never prevents session freeze — all steps are independent.

04
Happy Path

Clean requests pass through untouched. The engine is invisible when nothing is wrong.

The vast majority of agent traffic is clean. Those requests pass through CASA-AI with less than 2ms of added overhead and zero modification to the token stream. The engine is architected for this — policy evaluation is a single in-memory PreparedEvalQuery lookup against the OPA engine, not a network call, not a database read. It is designed to be completely transparent on the happy path, and decisive the moment it is needed.

Common Questions
How does the license key work in an air-gapped environment?
The license key is an Ed25519-signed JSON payload passed as an environment variable (CASA_LICENSE_KEY). The engine validates it against a public key compiled into the binary at build time. Zero outbound network calls are made at any point during validation — proven by running in a fully network-blocked container with iptables DROP ALL outbound.
Can I switch tiers mid-contract?
Yes. Tier upgrades take effect immediately — a new license key is issued reflecting your new tier limits. For annual contracts, the remaining period is prorated. Downgrades take effect at the next billing cycle. Contact shivangace001@gmail.com to arrange any tier change.
What payment methods are accepted?
All major Indian payment methods via Razorpay — UPI, NEFT, IMPS, debit/credit cards, net banking. For enterprise contracts (ENTERPRISE and above), we also accept bank transfer / NEFT directly with a formal purchase order. GST invoice provided for all payments.
How quickly is the license key issued after payment?
Razorpay sends a subscription.activated webhook to our license server. The Ed25519-signed key is generated and emailed within minutes of payment confirmation. The license-server code (cmd/license-server/) is in the public repository.
Does CASA-AI send any data to your servers?
No. The engine makes zero outbound network calls in normal operation. License validation uses an embedded public key — no license server check. Audit logs are written to your local filesystem only. The only outbound connection is the webhook URL you configure (default: disabled). We cannot see your prompts, agents, or audit logs. Architecturally impossible.
