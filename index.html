A
Context & Reasoning Tracker

The most novel module in CASA-AI and the layer no competing product has. Intercepts raw Server-Sent Events token streams from any OpenAI-compatible LLM, reassembles fragmented chunks into complete Thought-Action-Observation steps, and builds a live intent graph per session. This is where real leaks happen — and where every other security tool is completely blind.

SSE Token Reassembly

Chunks arrive as partial strings. A PAN number like "ABCDE1234F" may split across 3–4 chunks. The interceptor buffers and reassembles before running any regex — catching leaks that line-by-line scanners miss completely.

TAO Loop Classification

Each reassembled line is classified as Thought / Action / Observation and added to the session's in-memory intent graph. The compliance engine evaluates the full graph — not isolated lines in isolation.

MCP Tool Call Interception

Model Context Protocol tool calls are intercepted before dispatch. Tool name, provider country, and parameters are extracted and evaluated against the approved_tools allowlist in casa.yaml.

Zero-Copy Pass-Through

Clean tokens pass through with <2ms overhead. The engine is invisible on the happy path — decisive only when a violation fires. SSE connection is severed mid-stream on breach detection.

Automated Circuit-Breaker

When a breach fires, the circuit-breaker executes synchronously — not advisory, not logged-and-continue. The SSE stream is severed, IAM credentials are invalidated via real cloud APIs, and a signed webhook alert is dispatched. All four steps are independent — a failed IAM revocation never prevents session freeze. Tested live against real AWS, not simulated.

PutRolePolicy attaches a deny-all inline policy with DateLessThan on aws:TokenIssueTime. All sessions before the breach timestamp are immediately invalid. Tested live against AWS account 083334184188 — confirmed in 3.0 seconds.

GCP Service Account Disable

GCP IAM API disables the service account bound to the agent's Workload Identity. normalizeGCPServiceAccountName() handles both bare email and full resource name formats. Independent unit tests — all passing.

Azure Graph API Revocation

Two steps: revokeSignInSessions (invalidates refresh tokens) + accountEnabled=false (blocks new token issuance). Microsoft Graph API with HMAC-SHA256 signed Bearer token. Code complete, Azure tenant test pending.

HMAC-Signed Webhook Alerts

On breach, a JSON payload signed with HMAC-SHA256 is POSTed to the operator's configured endpoint. VerifyWebhookSignature() lets receiving systems authenticate that the alert came from CASA-AI — wrong secret = rejected, tampered payload = rejected.

SHA-256 Chained Tamper-Evident Audit Log

Every evaluation, breach, and remediation written to an append-only JSONL file with cryptographic chaining. Any retrospective edit, deletion, or reordering of entries is mathematically detectable. The Verify() function checks every entry in sequence — returns CHAIN VALID or the exact entry where tampering occurred. An auditor running Verify() gets an unambiguous, court-admissible answer.

SHA-256 Hash Chaining

Each entry's hash covers its own content with Hash field empty. The next entry's prev_hash links to it. First entry uses a sentinel hash of 64 zeros. Structurally identical to the Bitcoin blockchain's hash-chain mechanism.

Sequence Gap Detection

Every entry carries a monotonically increasing sequence number. Deleting an entry causes a seq gap (1 → 3) caught by Verify() independently of hash checking. Two independent tamper indicators per entry.

Chain Continuation on Restart

On container restart, Open() reads the last entry to continue the chain correctly. Proven in TestLogger_ContinuesChainOnRestart — 3 entries across a simulated restart verify cleanly as one unbroken chain.

Immutable Cloud Export

ExportAuditLog() verifies chain integrity before uploading to S3/GCS/Azure Blob with object lock enabled. Refuses to export tampered logs. Legally immutable for RBI (3yr) and SEBI (5yr) retention requirements.

Common Questions
How does the license key work in an air-gapped environment?
The license key is an Ed25519-signed JSON payload passed as an environment variable (CASA_LICENSE_KEY). The engine validates it against a public key compiled into the binary at build time. Zero outbound network calls are made at any point during validation — proven by running in a fully network-blocked container with iptables DROP ALL outbound.
Can I switch tiers mid-contract?
Yes. Tier upgrades take effect immediately — a new license key is issued reflecting your new tier limits. For annual contracts, the remaining period is prorated. Downgrades take effect at the next billing cycle. Contact shivangace001@gmail.com to arrange any tier change.
What payment methods are accepted?
All major Indian payment methods via Razorpay — UPI, NEFT, IMPS, debit/credit cards, net banking. For enterprise contracts (ENTERPRISE and above), we also accept bank transfer / NEFT directly with a formal purchase order. GST invoice provided for all payments.
How quickly is the license key issued after payment?
Razorpay sends a subscription.activated webhook to our license server. The Ed25519-signed key is generated and emailed within minutes of payment confirmation. The license-server code (cmd/license-server/) is in the public repository.
Does CASA-AI send any data to your servers?
No. The engine makes zero outbound network calls in normal operation. License validation uses an embedded public key — no license server check. Audit logs are written to your local filesystem only. The only outbound connection is the webhook URL you configure (default: disabled). We cannot see your prompts, agents, or audit logs. Architecturally impossible.
What does "2 months free" mean exactly?
Annual contracts are billed as 10 months instead of 12 — you pay for 10, get 12. BASIC annual: ₹40,000 total (vs ₹48,000 monthly). ENTERPRISE annual: ₹5,00,000 total (vs ₹6,00,000 monthly). BIG INFRA annual: ₹12,00,000 total (vs ₹14,40,000 monthly). Applies to all plans, auto-applied at checkout.

GET /stream — SSE Interception Proxy

The primary interface for streaming LLM agents. CASA-AI acts as a transparent SSE proxy — all token chunks pass through while the engine evaluates each reassembled reasoning step. On breach, the stream is severed mid-flight and a casa_breach event is injected. The agent never receives another token.

GET http://casa-ai:8088/stream ?session_id=<id>&scenario=<clean|leaky|inject>

How the proxy works

1
Agent opens SSE connection to CASA-AI instead of the LLM directly
2
CASA-AI opens upstream connection to the real LLM provider and begins forwarding chunks
3
Each chunk buffered and reassembled into complete TAO steps (PAN across 3 chunks → caught at reassembly)
4
Completed step evaluated against all 5 detection layers in <2ms via embedded OPA
5
Clean steps forwarded to agent unchanged — invisible on the happy path
6
Violation: stream severed, circuit-breaker fires, event: casa_breach sent to agent

Breach event payload

textSSE stream — breach severance
data: Thought: I need to fetch the customer record... data: Action: read_file(path="/crm/customer_8821.json") data: Observation: Found — PAN: ABCDE12█ [STREAM CUT] event: casa_breach data: { "violation": "PII_LEAK_IN_REASONING", "session_id": "agent-prod-42", "action": "freeze_session", "circuit_breaker": true } event: done data: stream terminated by CASA-AI · session frozen

1. Container Hardening

The CASA-AI Docker image is built using a multi-stage Dockerfile targeting gcr.io/distroless/static-debian12:latest-amd64 as the runtime layer. The container has no shell, no package manager, no debug utilities, and no writable root filesystem. All processes run as UID 65532 (non-root) enforced at the image level.

2. CVE Scanning

Trivy vulnerability scanning runs on every commit to the main branch via GitHub Actions. The CI pipeline is configured to fail on any HIGH or CRITICAL CVE finding. The current image has zero HIGH or CRITICAL CVEs as of the last scan.

3. Cryptographic Key Security

The Ed25519 public key used for license validation is embedded into the binary at compile time using //go:embed. The corresponding private key is held exclusively by CASA-AI and is never included in any distributed artifact. License payload forgery has been tested — modified payloads and wrong keys are rejected immediately.

4. Zero Outbound Architecture

The engine makes no outbound network calls in normal operation. This has been verified by running the engine in a container with iptables DROP ALL outbound rules applied — the engine starts, validates the license, and processes evaluations correctly with no external connectivity.

5. Reporting a Vulnerability

If you discover a security vulnerability in CASA-AI, please report it responsibly by emailing shivangace001@gmail.com with subject line [SECURITY] CASA-AI Vulnerability Report. Please do not disclose vulnerabilities publicly until we have had reasonable time to investigate and patch. We aim to respond to security reports within 48 hours.

6. Audit Log Integrity

All engine events are written to a SHA-256 chained JSONL audit log. The chain is verified by the Verify() function which checks every entry's hash, prev_hash link, and sequence number. Any tampering — byte flip, deletion, or reordering — is detected and reported with the exact entry number where the chain broke.
