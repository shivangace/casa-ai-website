Mid-Stream SSE Interception

CASA-AI intercepts the raw Server-Sent Events token stream from any OpenAI-compatible LLM before it reaches the agent's logic layer. Every token is captured, fragmented chunks are reassembled into complete Thought-Action-Observation steps, and the full reasoning chain is evaluated mid-flight — not after the fact. This is the layer every competing product misses entirely.

Token-Level Reassembly

"ABCDE1234F" (a PAN number) may arrive as ["ABCDE", "123", "4F"] across 3 chunks. The interceptor buffers and reassembles before regex — catching leaks that line-by-line scanners miss completely.

TAO Loop Classification

Each line is classified as Thought / Action / Observation and added to the session's intent graph. The engine evaluates the complete graph — not isolated lines, the full context of what the agent is doing.

Synchronous Severance

On violation, the SSE stream is cut at the proxy layer. The agent receives event: casa_breach — never another content token. Breach happens before any compromised data can be acted upon.

Zero Latency on Happy Path

Clean requests pass through with <2ms overhead. TestEvaluate_LatencyBudget confirms policy evaluation at 1.28ms — well within the 3ms production target. The engine is invisible when there is nothing to catch.

PII Detection — Indian Financial Data

Regex-based PII detection covering the most sensitive Indian financial identifiers. Evaluated against both the agent's prompt AND every step of the intermediate reasoning chain — the exact attack surface that leaks data in production deployments. Configurable sensitivity per deployment via custom Rego policy extension.

PAN Card Detection

Pattern: [A-Z]{5}[0-9]{4}[A-Z]

Catches PAN numbers split across multiple SSE tokens during reassembly. Proven in TestEvaluate_BlocksPIIInReasoningChain with a real PAN embedded in an observation step.

Aadhaar Number Detection

12-digit Aadhaar numbers detected via regex. Tested against both raw numbers and space-separated formats (XXXX XXXX XXXX) commonly returned by document parsing tools. DIN and Form 16 patterns also covered.

Credit / Debit Card

13–19 digit patterns covering both space-separated and dash-separated formats. Prevents agent memory from leaking card data retrieved from customer records in CRM systems. Luhn check awareness built in.

Mobile + Email PII

Indian mobile numbers (10-digit, +91 prefix variants) and email addresses detected in both prompt and reasoning chain. Configurable false-positive sensitivity per deployment — test emails can be whitelisted.

SHA-256 Chained Tamper-Evident Audit Log

Every evaluation, breach, and remediation written to an append-only JSONL file with cryptographic chaining. Any retrospective edit, deletion, or reordering of entries is mathematically detectable. The Verify() function checks every entry in sequence — returns CHAIN VALID or the exact entry where tampering occurred. An auditor running Verify() gets an unambiguous, court-admissible answer.

SHA-256 Hash Chaining

Each entry's hash covers its own content with Hash field empty. The next entry's prev_hash links to it. First entry uses a sentinel hash of 64 zeros. Structurally identical to the Bitcoin blockchain's hash-chain mechanism.

Sequence Gap Detection

Every entry carries a monotonically increasing sequence number. Deleting an entry causes a seq gap (1 → 3) caught by Verify() independently of hash checking. Two independent tamper indicators per entry.

Chain Continuation on Restart

On container restart, Open() reads the last entry to continue the chain correctly. Proven in TestLogger_ContinuesChainOnRestart — 3 entries across a simulated restart verify cleanly as one unbroken chain.

Immutable Cloud Export

ExportAuditLog() verifies chain integrity before uploading to S3/GCS/Azure Blob with object lock enabled. Refuses to export tampered logs. Legally immutable for RBI (3yr) and SEBI (5yr) retention requirements.

// Verify checks every entry in the audit log for chain integrity. // Returns the count of valid entries, or an error naming the broken entry. func Verify(path string) (int, error) { f, _ := os.Open(path) defer f.Close() prevHash := strings.Repeat("0", 64) // sentinel scanner := bufio.NewScanner(f) count := 0 for scanner.Scan() { var entry LogEntry json.Unmarshal(scanner.Bytes(), &entry) // 1. Sequence gap detection if entry.Sequence != count+1 { return count, fmt.Errorf("sequence gap at entry %d", count+1) } // 2. Hash chain verification if entry.PrevHash != prevHash { return count, fmt.Errorf("chain broken at entry %d", entry.Sequence) } // 3. Content hash validation computed := computeHash(entry) if computed != entry.Hash { return count, fmt.Errorf("hash mismatch at entry %d — content tampered", entry.Sequence) } prevHash = entry.Hash count++ } return count, nil // "CHAIN VALID: N entries verified" }

Satellite Registry

Thread-safe registry tracking ID, cluster name, endpoint, policy version, active sessions, total evals, and health status per satellite. Status: healthy → stale (2 missed) → offline (5 missed).

Policy Push on Version Mismatch

Heartbeat response includes needs_update: true when satellite's policy_version SHA-256 differs from canonical. Satellite calls GET /cluster/policy to pull the updated bundle automatically.

Fleet Session Counting

ActiveSessionsFleetTotal() sums active sessions across all healthy satellites. Fleet-wide breach rates visible via the central Prometheus endpoint and pre-built Grafana dashboard JSON.

Prometheus Alert — SatelliteOffline

Alert fires when any satellite goes offline for >5 minutes. Pre-built rule ships in deployments/prometheus/casa-ai-alerts.yaml. Drops directly into Alertmanager — no configuration needed.
