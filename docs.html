Docs / Quick Start
Deploy CASA-AI in 60 seconds

CASA-AI is a single Docker container. Point your agent's LLM API base URL at the container. One environment variable change — no SDK modifications, no agent code changes.

Docker 24+ required No SDK changes Valid license key required
Prerequisites
1
Docker 24+ or Kubernetes 1.28+
Running in your private VPC or on-premise cluster. The container requires no internet connectivity after the image is pulled.
2
Valid CASA_LICENSE_KEY
Issued within minutes of Razorpay payment. Ed25519-signed — validated entirely offline against the embedded public key.
3
Your LLM provider endpoint
Any OpenAI-compatible API — OpenAI, Anthropic, AWS Bedrock, Azure OpenAI, local Ollama. CASA-AI acts as a transparent proxy.
Run with Docker
bash
docker run -d \ --name casa-ai \ -p 8088:8088 \ -e CASA_LICENSE_KEY="your-ed25519-signed-key" \ -e LLM_UPSTREAM="https://api.openai.com" \ -e LOG_LEVEL="info" \ -v $(pwd)/policies:/policies:ro \ ghcr.io/shivangace/casa-ai-core:latest
Point your agent at CASA-AI

Change one environment variable in your agent application. No code changes required.

bash — agent application
# Before — direct to OpenAI OPENAI_API_BASE=https://api.openai.com/v1 # After — proxied through CASA-AI OPENAI_API_BASE=http://localhost:8088/v1 # CASA-AI intercepts, evaluates, and forwards clean traffic. # Violated requests are blocked before they reach the LLM.
Verify it's running
bash
curl http://localhost:8088/health # Expected response: { "status": "ok", "version": "1.0.0", "license": { "tier": "ENTERPRISE", "tenant_id": "your-org", "max_agents": 15, "expires_at": "2027-07-01T00:00:00Z" }, "active_agents": 0, "uptime_seconds": 12 }
That's it. Your AI agents are now fully governed at runtime. Every reasoning chain is intercepted, every tool call validated, every violation blocked before it reaches production.
Docs / Configuration
Configuration Reference

CASA-AI is configured via environment variables and an optional casa.yaml file mounted into the container. The YAML file hot-reloads — changes take effect within 2 seconds without restart.

Environment Variables
VariableTypeDefaultDescription
CASA_LICENSE_KEYstringrequiredEd25519-signed license payload. Validated offline against embedded public key.
LLM_UPSTREAMstringrequiredBase URL of your LLM provider (e.g., https://api.openai.com). CASA-AI proxies to this endpoint.
LOG_LEVELstringinfoLogging verbosity: debug, info, warn, error. All logs go to stdout.
POLICY_DIRstring/policiesPath to Rego policy files inside the container. Mount your policy directory here.
CONFIG_PATHstring/configs/casa.yamlPath to the YAML configuration file. Hot-reloaded on change.
WEBHOOK_URLstring—ENTERPRISE+. HMAC-SHA256 signed JSON webhook dispatched on every compliance violation.
WEBHOOK_SECRETstring—ENTERPRISE+. Secret used to sign the webhook payload for verification by your endpoint.
AUDIT_LOG_PATHstring/var/log/casa-ai/audit.jsonlPath for the SHA-256 chained audit log. Mount a persistent volume here.
casa.yaml — Full Reference

Docs / License Setup
License Key Setup

CASA-AI uses Ed25519-signed license payloads validated entirely offline. No outbound calls, no license servers, no internet dependency. Air-gap compatible by architecture.

Getting your license key
1
Purchase a plan
Visit pricing page and select your tier. Pay via Razorpay — UPI, netbanking, card all accepted.
2
Receive key via email
Ed25519-signed JWT delivered to your email within minutes of payment confirmation. Contains your tenant_id, tier, max_agents, and expiry.
3
Set environment variable
Pass the key as CASA_LICENSE_KEY environment variable to the container. Never commit it to source control.
License payload structure
json — decoded license payload (example)
{ "tenant_id": "acme-corp-india", "tier": "ENTERPRISE", "max_agents": 15, "features": [ "rbi_ai_governance", "dpdp_act_2023", "eu_ai_act", "custom_rego", "webhook_alerts" ], "issued_at": "2026-07-01T00:00:00Z", "expires_at": "2027-07-01T00:00:00Z" // Signed with Ed25519 — tamper = instant rejection }
Agent limit enforcement: Attempting to register agent N+1 past your tier limit returns HTTP 429 Too Many Requests immediately. The limit is enforced in Go code at the session registry level — there is no UI bypass.
Docs / API / POST /evaluate
POST /evaluate

Evaluate a single agent prompt + reasoning chain snapshot against all active compliance policies. Returns a verdict synchronously in under 2ms.

POST/v1/evaluate
REQUEST BODY — application/json
session_idstringUnique identifier for this agent session. Used to enforce per-session agent limits.
agent_payloadobjectContains prompt (string) — the surface-level user prompt sent to the agent.
reasoning_chainarrayArray of {type: "Thought|Action|Observation", content: string} steps captured so far.
tool_callsarrayArray of {tool_name, provider_country, resource_path} MCP tool calls to validate.
compliance_profileobjectOverride profile for this request. strict_sovereignty: bool, risk_threshold: float.
bash — example request
curl -X POST http://localhost:8088/v1/evaluate \ -H "Content-Type: application/json" \ -d '{ "session_id": "agent-prod-41", "agent_payload": { "prompt": "Translate this customer document." }, "reasoning_chain": [ {"type": "Thought", "content": "I need to extract the customer name first."}, {"type": "Observation", "content": "Customer: Rahul Sharma, PAN: ABCDE1234F"} ], "tool_calls": [ {"tool_name": "translate_text", "provider_country": "US"} ], "compliance_profile": {"strict_sovereignty": true} }'
json — BLOCK response
{ "allow": false, "violations": [ "PII_LEAK_IN_REASONING: PAN pattern in Observation step", "SOVEREIGNTY_VIOLATION: provider_country US != IN" ], "circuit_breaker_fired": true, "eval_latency_ms": 1.28, "audit_entry_id": 47 }
Docs / API / GET /stream
GET /stream (SSE Proxy)

The primary interception endpoint. CASA-AI acts as a transparent SSE proxy between your agent and the LLM provider. Token chunks are intercepted, reassembled, classified, and evaluated mid-stream.

GET/v1/chat/completions (SSE)
BEHAVIOR
Clean trafficToken chunks pass through with under 2ms overhead. The agent receives responses normally.
On violationStream severed mid-chunk. Agent receives no further output. Circuit-breaker fires synchronously.
HeadersPass all OpenAI-compatible headers including Authorization: Bearer sk-.... CASA-AI forwards them to your upstream.
Zero SDK changes required. Set OPENAI_API_BASE=http://localhost:8088/v1 in your agent environment. All SDKs (LangChain, LlamaIndex, AutoGen, raw openai-python) work without modification.

Docs / Deployment / Docker
Docker Deployment

The recommended way to run CASA-AI in production. Uses the hardened distroless image — no shell, no package manager, UID 65532 non-root, 8MB total size.

Production docker-compose.yml
yamldocker-compose.yml
version: '3.8' services: casa-ai: image: ghcr.io/shivangace/casa-ai-core:latest restart: unless-stopped ports: - "8088:8088" environment: CASA_LICENSE_KEY: "${CASA_LICENSE_KEY}" LLM_UPSTREAM: "https://api.openai.com" LOG_LEVEL: "info" WEBHOOK_URL: "${WEBHOOK_URL}" WEBHOOK_SECRET: "${WEBHOOK_SECRET}" volumes: - ./policies:/policies:ro # your Rego policy files - ./configs/casa.yaml:/configs/casa.yaml:ro - audit-log:/var/log/casa-ai # persist audit log read_only: true security_opt: - no-new-privileges:true cap_drop: - ALL healthcheck: test: ["CMD-SHELL", "wget -qO- http://localhost:8088/health | grep ok"] interval: 30s timeout: 5s retries: 3 volumes: audit-log:
Security note: read_only: true and cap_drop: ALL are strongly recommended. The distroless runtime has no shell — docker exec /bin/sh returns "no such file or directory".

Kubernetes / Helm Deployment

The included Helm chart deploys CASA-AI as a Kubernetes service. The chart handles RBAC, secret mounting, liveness/readiness probes, and optional HPA.

Install via Helm
bash
# Add the CASA-AI Helm repository helm repo add casa-ai https://charts.casa-ai.in helm repo update # Create secret from your license key kubectl create secret generic casa-ai-license \ --from-literal=CASA_LICENSE_KEY="your-signed-key" # Install with your values helm install casa-ai casa-ai/casa-engine \ --namespace casa-ai \ --create-namespace \ --set licenseSecretName=casa-ai-license \ --set llmUpstream=https://api.openai.com \ --set replicaCount=2

Docs / Deployment / Air-Gap Setup
Air-Gap Deployment

CASA-AI is air-gap compatible by architecture. The license validation uses an embedded Ed25519 public key — zero outbound calls. Verified with iptables DROP ALL outbound.

Verify air-gap operation
bash — test air-gap mode
# Block all outbound traffic iptables -I OUTPUT -j DROP iptables -I OUTPUT -d 127.0.0.1 -j ACCEPT iptables -I OUTPUT -d ::1 -j ACCEPT # Start CASA-AI — should start, validate license, and operate normally docker run -d \ -e CASA_LICENSE_KEY="your-key" \ -e LLM_UPSTREAM="http://your-internal-ollama:11434" \ ghcr.io/shivangace/casa-ai-core:latest # Confirm health — proves zero outbound calls needed curl http://localhost:8088/health # Expected: {"status":"ok", "license":{"tier":"..."}, ...} # Clean up iptables rules iptables -D OUTPUT -j DROP

Docs / Compliance / Custom Rego Policies
Custom Rego Policies

Write your own compliance rules in Open Policy Agent's Rego language. Mount your .rego files into /policies/ — the engine hot-reloads changes atomically without restart. ENTERPRISE+ tier.

Input schema available in policy
json — input object available to Rego
{ "agent_payload": { "prompt": "string — the user's input prompt" }, "reasoning_chain": [ {"type": "Thought|Action|Observation", "content": "string"} ], "tool_calls": [ { "tool_name": "string", "provider_country": "IN|US|EU|...", "resource_path": "string" } ], "session": { "user_role": "string", "dual_approval_obtained": "bool" }, "compliance_profile": { "strict_sovereignty": "bool", "risk_threshold": "float" }, "policy": { "approved_tools": ["string"] } }
Custom policy example
regopolicies/custom_sebi.rego
package casa.ai.custom.sebi # Block trade execution without dual approval default unapproved_tool_call := false unapproved_tool_call if { some call in input.tool_calls call.tool_name == "execute_trade" not input.session.dual_approval_obtained } # Block access to contracts unless legal_team role unapproved_tool_call if { some call in input.tool_calls startswith(call.resource_path, "/contracts/") input.session.user_role != "legal_team" } # Add custom PII — internal employee IDs pii_detected if { regex.match( `EMP-[0-9]{6}`, input.agent_payload.prompt, ) }
Docs / Compliance / Audit Log Format
Audit Log Format

Every evaluation verdict is written to a SHA-256 chained JSONL file. Each entry includes the previous entry's hash — making any tampering immediately detectable. One line per evaluation.

Entry format
json — single audit entry (ALLOW)
{ "entry_id": 44, "timestamp": "2026-07-07T18:46:43.847Z", "session_id": "agent-prod-41", "verdict": "ALLOW", "violations": [], "eval_latency_ms": 0.847, "circuit_breaker": false, "framework": "NIST_AI_RMF", "entry_hash": "a7f3b2c1e4d9f823...", "prev_hash": "3d9e1a2f8b4c7e12..." }
json — single audit entry (BLOCK)
{ "entry_id": 46, "timestamp": "2026-07-07T18:46:45.123Z", "session_id": "agent-prod-43", "verdict": "BLOCK", "violations": [ "PII_LEAK_IN_REASONING: PAN pattern in Observation step", "SOVEREIGNTY_VIOLATION: provider_country US != IN" ], "eval_latency_ms": 1.28, "circuit_breaker": true, "remediation": [ "STREAM_SEVERED", "AWS_IAM_REVOKED: arn:aws:iam::083334184188:role/agent-role" ], "framework": "RBI_AI_GOVERNANCE", "entry_hash": "2b8f5e1d9a3c6f47...", "prev_hash": "e9d4c7a3f1b2e856..." }
Tamper detection

Each entry's entry_hash is SHA256(entry_data + prev_hash). To verify chain integrity:

bash — verify chain integrity
# CASA-AI includes a built-in verifier docker exec casa-ai /casa-ai-engine verify-audit \ --file /var/log/casa-ai/audit.jsonl # Output on clean chain: Verified 12,847 entries. Chain integrity: OK. # Output on tampered chain: Chain integrity FAILED at entry #46. Expected hash: 2b8f5e1d... Got: 9f3a1c2d... This entry has been modified or an entry has been deleted.
