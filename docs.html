Docs / Quick Start

Deploy CASA-AI in 60 seconds

CASA-AI is a single Docker container. Point your agent's LLM API base URL at the container. One environment variable change — no SDK modifications, no agent code changes. The engine intercepts, evaluates, and enforces from the first token.

Prerequisites

1
Docker 24+ or Kubernetes 1.28+ in your private VPC
2
A valid CASA_LICENSE_KEY — issued within minutes of Razorpay payment confirmation
3
Your LLM provider endpoint — any OpenAI-compatible API (OpenAI, Anthropic, Bedrock, local Ollama)

Run with Docker

bashTerminal
# Pull the CASA-AI engine image docker pull ghcr.io/shivangace/casa-ai-core:latest # Run with your license key and LLM target docker run -d \ --name casa-ai \ -p 8088:8088 \ -e CASA_LICENSE_KEY="your_signed_license_key_here" \ -e LLM_UPSTREAM="https://api.openai.com" \ -e LOG_LEVEL="info" \ -v $(pwd)/policies:/policies \ -v $(pwd)/logs:/var/log/casa-ai \ ghcr.io/shivangace/casa-ai-core:latest # Verify the engine is live curl http://localhost:8088/healthz # → {"status":"ok","engine":"running","license_tier":"BASIC","agents_active":0}

Point your agent at CASA-AI

Change one environment variable. Your agent now routes all LLM calls through CASA-AI automatically — no SDK changes, no code modifications.

bashAgent environment
# Before — direct to LLM provider (CASA-AI sees nothing) OPENAI_API_BASE=https://api.openai.com # After — routed through CASA-AI (full interception active) OPENAI_API_BASE=http://casa-ai:8088 # All existing agent code continues to work identically. # CASA-AI transparently proxies clean traffic to the LLM. # LangChain, AutoGen, CrewAI, custom agents — all compatible.

Test the interception

bashVerify PII detection is active
# Send a test evaluation with a PAN card in the payload curl -X POST http://localhost:8088/evaluate \ -H "Content-Type: application/json" \ -d '{ "session_id": "test-001", "ai_system_id": "my-agent-v1", "agent_payload": { "prompt": "Customer PAN: ABCDE1234F — process refund" }, "reasoning_chain": [], "tool_calls": [] }' # Expected response — breach detected, stream would be severed { "allow": false, "violations": ["PII_LEAK_DETECTED: sensitive identifier pattern found"], "trigger_circuit_breaker": true, "eval_latency_us": 1284 }
💡
Happy path latency: Clean requests pass through with <2ms overhead. TestEvaluate_LatencyBudget confirms 1.28ms policy evaluation — well within the 3ms production target.

casa.yaml — Full Configuration Reference

All CASA-AI configuration lives in a single casa.yaml file mounted at /configs/casa.yaml inside the container. The engine watches this file — changes to compliance profiles and policy paths are hot-reloaded without a container restart.

yamlconfigs/casa.yaml — full annotated example
# CASA-AI Engine Configuration # Hot-reloaded on change — no container restart required server: port: 8088 log_level: "info" # debug | info | warn | error read_timeout_s: 30 write_timeout_s: 60 upstream: llm_base_url: "https://api.openai.com" # Any OpenAI-compat endpoint timeout_ms: 30000 engine: policy_dir: "/policies" # Directory watched for .rego files eval_timeout_ms: 3 # Circuit-break eval if over budget session_ttl_minutes: 60 # Evict idle sessions after N minutes max_token_budget: 50000 # Per session (BASIC), 500K (ENT), unlimited (BIG) compliance_profiles: nist_ai_rmf: enabled: true # Active on all tiers policy_path: "policies/nist_ai_rmf.rego" rbi_ai: enabled: true # ENTERPRISE+ only policy_path: "policies/rbi_ai_governance.rego" dpdp: enabled: true policy_path: "policies/dpdp_act.rego" eu_ai_act: enabled: false # Toggle per deployment region policy_path: "policies/eu_ai_act.rego" custom: enabled: true # ENTERPRISE+: mount your own .rego policy_path: "policies/my_corporate_policy.rego" sovereignty: strict_mode: true # Block all non-IN providers (RBI Control 3) allowed_countries: ["IN", "SG", "AE"] approved_tools: # MCP tool allowlist — block everything else - "read_file" - "search_web" - "query_database" - "send_email" # Add your approved MCP tools here audit: log_path: "/var/log/casa-ai/audit.jsonl" export: enabled: false # Off by default — data stays in VPC target: "s3://your-bucket/casa-ai-audit/" object_lock: true webhooks: # ENTERPRISE+ breach_url: "https://hooks.slack.com/..." hmac_secret: "your-hmac-secret" # Used to sign webhook payloads # Cloud credential revocation targets breaker: aws: enabled: true role_arn: "arn:aws:iam::123456789:role/casa-ai-breaker" gcp: enabled: false service_account: "casa-ai@project.iam.gserviceaccount.com" azure: enabled: false tenant_id: "your-azure-tenant-id"

Key configuration fields

FieldDefaultDescription
server.port8088Engine listening port. Map to host port of your choice.
engine.eval_timeout_ms3OPA evaluation budget per request. Exceeding this returns DENY immediately.
engine.session_ttl_minutes60Idle sessions are evicted. Reduces memory footprint on long-running containers.

Docs / License Setup

License Key — Setup & Validation

CASA-AI uses an Ed25519-signed JWT-like license payload. The public key is compiled into the binary at build time. Validation makes zero outbound network calls — fully air-gap compatible by architecture. The key is passed as a single environment variable.

Obtaining your license key

1
Pay via Razorpay on the pricing page — UPI, NEFT, cards, net banking accepted
2
Razorpay fires subscription.activated webhook to our license server
3
License server generates an Ed25519-signed payload for your tenant_id and tier
4
Signed key emailed to your account within minutes of payment confirmation
5
Pass as CASA_LICENSE_KEY environment variable — engine validates on startup

Setting the license key

bashDocker — environment variable
docker run -d \ -e CASA_LICENSE_KEY="eyJwYXlsb2FkIjp7InRlbmFudF9pZCI6IndzbC1wcm9kIiwidGllciI6Ik..." \ ghcr.io/shivangace/casa-ai-core:latest
yamlKubernetes secret + deployment
# Create secret kubectl create secret generic casa-ai-license \ --from-literal=CASA_LICENSE_KEY="your_signed_key" # Reference in deployment env: - name: CASA_LICENSE_KEY valueFrom: secretKeyRef: name: casa-ai-license key: CASA_LICENSE_KEY

{ "payload": { "tenant_id": "wsl-prod-tenant", "tier": "ENTERPRISE", // BASIC | ENTERPRISE | BIG_INFRA | CUSTOM "max_agents": 15, // 2 | 15 | -1 (unlimited) "features": ["custom_rego", "webhooks", "rbi", "dpdp"], "issued_at": "2026-07-04T00:00:00Z", "expires_at": "2027-07-04T00:00:00Z" }, "signature": "Ed25519-base64-signature-over-payload..." }

The engine reads max_agents from the decoded payload and enforces it at the session registry level. A BASIC tier key with max_agents: 2 attempting to register a third agent session receives HTTP 429:

Docs / API Reference / POST /evaluate

POST /evaluate

Synchronous policy evaluation endpoint. Submit an agent's current prompt, reasoning chain snapshot, and tool calls. Returns an allow/deny verdict with structured violation messages in under 2ms. Used for non-streaming agents and batch evaluation workflows.

POST http://casa-ai:8088/evaluate Content-Type: application/json

Request body

jsonRequest — full schema
{ "session_id": "agent-prod-42", // Required — unique per agent session "ai_system_id": "crm-agent-v2", // Required — registered model ID "agent_payload": { "prompt": "Fetch customer record for account 8821" }, "reasoning_chain": [ // TAO steps so far this session { "type": "Thought", "content": "I need to look up account 8821" }, { "type": "Action", "content": "read_file('/crm/8821.json')" }, { "type": "Observation", "content": "name: Rajesh Kumar, PAN: ABCDE1234F" } ], "tool_calls": [ // MCP tool calls being made { "tool_name": "read_file", "provider_country": "IN", "external": false } ], "compliance_profile": { "strict_sovereignty": true } }

Response — DENY (breach detected)

jsonHTTP 200 — DENY verdict
{ "allow": false, "violations": [ "PII_LEAK_DETECTED: sensitive identifier pattern found in agent traffic" ], "trigger_circuit_breaker": true, "eval_latency_us": 1284, "session_id": "agent-prod-42", "audit_entry_seq": 47 }

Response — ALLOW (clean)

jsonHTTP 200 — ALLOW verdict
{ "allow": true, "violations": [], "trigger_circuit_breaker": false, "eval_latency_us": 847, "session_id": "agent-prod-42", "audit_entry_seq": 46 }

Response fields

FieldTypeDescription
allowboolTrue if all 5 detection layers cleared. False if any violation fired.
violationsstring[]Structured violation messages. Empty array on ALLOW. Directly usable in EU AI Act Article 13 transparency reports.
trigger_circuit_breakerboolTrue when PII, injection, or exfiltration detected. Engine fires breaker synchronously before returning.
eval_latency_usintOPA evaluation time in microseconds. p99 target: <2000μs (2ms).
audit_entry_seqintSequence number of the audit log entry written for this evaluation.
Docs / API Reference / GET /stream

GET /stream — SSE Interception Proxy

The primary interface for streaming LLM agents. CASA-AI acts as a transparent SSE proxy — all token chunks pass through while the engine evaluates each reassembled reasoning step. On breach, the stream is severed mid-flight and a casa_breach event is injected. The agent never receives another token.

GET http://casa-ai:8088/stream ?session_id=<id>&scenario=<clean|leaky|inject>

How the proxy works

1
Agent opens SSE connection to CASA-AI instead of the LLM directly
2
CASA-AI opens upstream connection to the real LLM provider and begins forwarding chunks
3
Each chunk buffered and reassembled into complete TAO steps (PAN across 3 chunks → caught at reassembly)
4
Completed step evaluated against all 5 detection layers in <2ms via embedded OPA
5
Clean steps forwarded to agent unchanged — invisible on the happy path
6
Violation: stream severed, circuit-breaker fires, event: casa_breach sent to agent

Breach event payload

textSSE stream — breach severance
data: Thought: I need to fetch the customer record... data: Action: read_file(path="/crm/customer_8821.json") data: Observation: Found — PAN: ABCDE12█ [STREAM CUT] event: casa_breach data: { "violation": "PII_LEAK_IN_REASONING", "session_id": "agent-prod-42", "action": "freeze_session", "circuit_breaker": true } event: done data: stream terminated by CASA-AI · session frozen
💡
LangChain integration: Set openai.base_url = "http://casa-ai:8088" in your LangChain ChatOpenAI constructor. All streaming calls automatically route through CASA-AI. Zero LangChain code changes required.

Docs / Core Concepts / Audit Log

SHA-256 Chained Audit Log

Every evaluation, breach, and remediation action is written to an append-only JSONL file with cryptographic hash chaining. Any retrospective edit, deletion, or reordering is mathematically detectable. Run Verify(path) to get an unambiguous tamper status — suitable for regulatory inspection.

Log entry schema

json/var/log/casa-ai/audit.jsonl — single entry
{ "seq": 47, "ts": "2026-07-04T18:46:45.391Z", "event": "COMPLIANCE_BREACH", "session_id": "agent-prod-42", "allow": false, "violations": ["PII_LEAK_DETECTED: PAN pattern in observation step 3"], "latency_us": 1284, "prev_hash": "9e451960de03ae37e4a5ec9a9a586d46", "hash": "c7d60a1374fc938c4742920af7e9cff8" }

Verifying chain integrity

bashRun chain verification
curl -X POST http://localhost:8088/audit/verify # → {"status":"CHAIN_VALID","entries_verified":1847,"first_seq":1,"last_seq":1847} # On tamper detected: # → {"status":"CHAIN_BROKEN","broken_at_seq":142,"error":"hash mismatch at entry 142"}
PROVEN: TestLogger_DetectsTamperedEntry (byte flip caught) · TestLogger_DetectsDeletedEntry (seq gap caught) · TestLogger_ContinuesChainOnRestart (restart continuity verified) — all PASS.

Docs / Core Concepts / Multi-Cluster

Multi-Cluster Orchestration — BIG INFRASTRUCTURE

One central CASA-AI instance acts as the policy server for satellite engine instances across multiple Kubernetes clusters. Satellites heartbeat every 60 seconds, pull updated policy bundles on version mismatch, and are automatically marked stale → offline on missed heartbeats. Fleet-wide metrics visible from the central Prometheus endpoint.

⚠️
BIG INFRASTRUCTURE tier required. Attempting to use cluster endpoints on BASIC or ENTERPRISE keys returns HTTP 403 with "feature_not_available".

Satellite registration

bashRegister satellite at startup
curl -X POST https://central-casa-ai:8088/cluster/register \ -H "Content-Type: application/json" \ -d '{ "id": "prod-india-1", "cluster_name": "ap-south-1", "endpoint": "http://10.0.1.5:8088" }' # Response { "status": "registered", "policy_version": "sha256:abc123..." }

Satellite heartbeat (every 60s)

bashHeartbeat + policy sync check
curl -X POST https://central-casa-ai:8088/cluster/heartbeat \ -d '{ "satellite_id": "prod-india-1", "policy_version": "sha256:abc123", "active_sessions": 7 }' # needs_update: true → satellite pulls /cluster/policy immediately { "status": "ok", "needs_update": true, "policy_version": "sha256:xyz789" }

Docs / Development / Custom Rego

Writing Custom Rego Policies — ENTERPRISE+

Full OPA v1 language access. Mount your .rego files into the /policies directory. The engine watches for changes and atomically hot-swaps the compiled OPA instance — zero sessions dropped, zero downtime. Failed compilations keep the existing policy serving.

Policy input schema

Your Rego policy receives the following input object on every evaluation:

jsoninput — available in every Rego rule
{ "session_id": "agent-42", "ai_system_id": "crm-agent-v2", "agent_payload": { "prompt": "..." }, "reasoning_chain": [{ "type": "Thought", "content": "..." }], "tool_calls": [{ "tool_name": "...", "provider_country": "IN", "external": false }], "compliance_profile":{ "strict_sovereignty": true }, "ai_system_id": "...", "ai_risk_level": "HIGH", "cost_center": "engineering", "data_classification":"RESTRICTED" }

Example — corporate policy

regopolicies/my_corporate_policy.rego
package my_company.compliance import rego.v1 # Block agents referencing competitor names violation contains msg if { regex.match(`(?i)(competitor_x|competitor_y)`, input.agent_payload.prompt) msg := "CORPORATE: competitor reference in agent prompt — blocked" } # All agent actions must declare a cost_center tag violation contains msg if { input.cost_center == "" msg := "CORPORATE: cost_center tag required on all agent sessions" } # RESTRICTED data cannot be sent to any external tool violation contains msg if { input.data_classification == "RESTRICTED" some call in input.tool_calls call.external == true msg := sprintf("CORPORATE: RESTRICTED data cannot reach external tool '%v'", [call.tool_name]) }

Activate in casa.yaml

yamlconfigs/casa.yaml
compliance_profiles: custom: enabled: true policy_path: "policies/my_corporate_policy.rego" # Save file — engine hot-reloads within ~1 second
⚠️
Safety layer always runs first. Custom policies run after the core 5-layer engine. They can add additional checks but cannot disable PII detection, injection detection, or the core allow/deny logic.
Docs / Development / Why CASA-AI

Why CASA-AI vs Alternatives

The core architectural difference: CASA-AI inspects the intermediate reasoning chain — the Thought-Action-Observation loop between the prompt and the response. No competing product does this. Every other tool is either prompt-only or response-only. The reasoning chain is where real data leaks happen in production AI agents.

The blind spot every competitor has

⚠️
The invisible leak: An agent retrieves a document. Its Observation step contains PAN: ABCDE1234F. The final API response is clean. Every existing tool — Lakera, Arthur AI, Guardrails AI — logged zero violations. CASA-AI intercepted the stream at the Observation step and severed the connection before the agent's Action step could exfiltrate it.
